## 1. Mission & Intent (P6: Point-of-View Anchoring)
- **Objective**: Implement Path C — make nakedagent's plugin seam honest about the "opinionated + autonomous" tension. Two mechanisms: (1) per-tool `.usage` attribute so a plugin replacing a tool replaces its prompt example too; (2) `DISABLE` convention so a plugin can remove a tool entirely, not just swap it.

- **Constraints**: stdlib-only, no new abstractions, no class hierarchy, no registration ceremony. Foundation stays at four tools. Path B (three-tier model) explicitly deferred.

## 4. Root Causes (DE1: Root Cause Analysis)
No deviations required root-causing. The one design decision worth tracing:
- Decision: `DISABLE` applied after all `TOOLS` merges (not interleaved).
- Why 1: If interleaved, a later plugin could re-add a disabled tool, making disable non-deterministic.
- Why 2: The omakase "send it back" promise requires disable to be final — a user who disables `shell` must not have it reappear.
- Root: Disable is the autonomy guarantee; it must win over any substitution. Documented in plugins.py:90-91 and tested in `test_disable_wins_over_substitution`.

## 6. Improves (IN20: Antigoals & Anti-Patterns Catalog)
- The static `SYSTEM_PROMPT` was originally a hardcoded string the seam couldn't reach — a plugin replacing `shell` would have been invisible to the prompt. This was the Gap 1 bug identified in the prior turn. Evidence: fixed in loop.py:50-85; regression-covered by test_plugin_usage_replaces_foundation_example.
- The original `load_plugins` had no disable mechanism — a user wanting a read-only agent could only swap tools for no-ops, and the model still saw the disabled tool's syntax in the prompt. This was Gap 2. Evidence: fixed in plugins.py:108-112; covered by test_disable_removes_foundation_tool and test_disabled_tool_absent_from_prompt.
- No end-to-end smoke test of a plugin replacing `shell` with different `.usage` was added to the suite — the unit tests cover the pieces (usage override, prompt build) but not the full "drop plugin → model sees new syntax" path through `run()`. The prior session's `_smoke.py` covered this manually but was deleted by the user and not ported to a permanent test. Evidence: no test in test_loop.py calls `run()` with a plugin-loaded registry.
