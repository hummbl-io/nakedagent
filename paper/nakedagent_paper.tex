\begin{abstract}
Autonomous software engineering agents driven by Large Language Models (LLMs) increasingly rely on expansive, multi-tiered dependency trees. Mainstream agent scaffolds (e.g., SWE-agent, Aider, OpenHands) import between 20 and 50+ third-party packages to facilitate HTTP communication, terminal UI rendering, provider protocol abstraction, and telemetry. While feature-rich, this architectural paradigm introduces substantial supply-chain vulnerability attack surfaces, runtime version fragility, and heavy deployment footprints. In this paper, we introduce \textbf{NakedAgent}, an autonomous coding agent engineered under a strict zero-runtime-dependency constraint: it executes entirely upon standard Python 3.10+ library modules (\texttt{urllib}, \texttt{json}, \texttt{subprocess}, \texttt{re}, and \texttt{hashlib}). NakedAgent decouples tool invocation from proprietary JSON function-calling schemas by utilizing a Markdown fenced code-block protocol, enabling consistent tool use across local models (such as Qwen 2.5-Coder and Gemma 3) and hosted endpoints. To establish auditability and non-repudiation, we model agent execution as a pure Mealy state machine reducer $(S_t, E_t) \to (S_{t+1}, A_{t+1})$, combined with SHA-256 Merkle-linked state hashing recorded in an append-only JSON Lines (JSONL) event log. This architecture enables zero-inference offline replay verification, validating tool execution histories without querying an LLM. We present empirical findings from a SWE-bench Lite pilot with local 12B models, delineating scaffold-induced failure modes from model-inherent reasoning bounds. Finally, we formulate the \textit{Omakase} extensibility doctrine, demonstrating how clean tool substitution seams empower extensible agent behaviors without framework bloat.
\end{abstract}

\section{Introduction}
Large Language Models have catalyzed a paradigm shift in software engineering automation~\cite{jimenez2024swebench,yang2024sweagent}. Modern coding agents read repositories, analyze stack traces, formulate patch hypotheses, and execute shell commands iteratively within feedback loops~\cite{yao2022react,shinn2023reflexion}. 

However, existing state-of-the-art coding agent frameworks—including Aider~\cite{gauthier2023aider}, SWE-agent~\cite{yang2024sweagent}, gptme~\cite{gptme2023}, and OpenHands~\cite{openhands2024}—are characterized by substantial dependency bloat. Typical installations pull in dozens of transitive packages spanning asynchronous networking libraries (\texttt{httpx}, \texttt{aiohttp}), rich terminal user interface kits (\texttt{rich}, \texttt{prompt\_toolkit}), distributed telemetry, and vendor-specific SDKs. 

This dependency proliferation incurs three critical systemic liabilities:
\begin{enumerate}
    \item \textbf{Supply-Chain Attack Surfaces}: Every additional package imported into an agent runtime introduces latent Common Vulnerabilities and Exposures (CVEs) and vectors for malicious compromise~\cite{ohm2020supplychain,ladisa2023supplychain}. Because coding agents inherently possess arbitrary shell execution and filesystem modification privileges within their execution sandbox, compromising an agent's dependency tree yields immediate remote code execution.
    \item \textbf{Version Fragility and Upstream Churn}: Minor version updates across transitive dependencies frequently break agent loops or corrupt internal prompt structures, undermining long-term production stability.
    \item \textbf{Container and Footprint Overhead}: Deploying agents into resource-constrained edge systems, embedded devices, or air-gapped secure enclaves becomes prohibitive when megabytes of external dependencies must be containerized and verified.
\end{enumerate}

To confront this trade-off, we propose \textbf{NakedAgent}. NakedAgent poses a fundamental research question: \textit{Can an autonomous coding agent achieve robust, auditable, and extensible code modification loops while maintaining exactly zero runtime dependencies?}

By restricting the runtime strictly to the standard Python library (\texttt{stdlib}), NakedAgent eliminates supply-chain exposure by construction. In this paper, we describe the architectural foundations of NakedAgent, its formal Mealy state machine execution lane, its tamper-evident Merkle event logging and offline replay mechanism, its empirical performance on SWE-bench Lite, and the Omakase extensibility doctrine.

\section{System Architecture}

\subsection{Foundational Invariants}
NakedAgent is governed by three primary architectural invariants:
\begin{equation}
    |\mathcal{D}_{\text{runtime}}| = 0
\end{equation}
where $\mathcal{D}_{\text{runtime}}$ represents the set of external third-party packages required to execute the agent.

\begin{equation}
    \forall t \in \mathcal{T}_{\text{foundation}}, \quad t: (\mathcal{A}_{\text{args}}, \mathcal{W}_{\text{context}}) \to \mathcal{R}_{\text{result}}
\end{equation}
where $\mathcal{T}_{\text{foundation}}$ is a minimal set of four deterministic tools operating within workspace $\mathcal{W}_{\text{context}}$.

\subsection{The Four Foundation Tools}
Rather than supplying extensive specialized APIs, NakedAgent constrains its foundation to four primitive tools:
\begin{itemize}
    \item \textbf{\texttt{read} [path]}: Inspects file contents within the workspace boundary. To assist model attention across long documents, line numbering is formatted cleanly, and path escapes traversing outside the target workspace are rejected.
    \item \textbf{\texttt{write} [path]}: Atomically writes or overwrites content to disk. Directory paths are created on demand, preventing path traversal vulnerabilities.
    \item \textbf{\texttt{patch} [path]}: Applies search-and-replace hunks. Rather than relying on non-deterministic diff algorithms, the patch tool requires exact, unique substring matches:
    \begin{equation}
        \text{count}(S_{\text{search}}, F_{\text{content}}) = 1
    \end{equation}
    If the search target occurs zero times (missing) or more than once (ambiguous), the patch fails closed with an explicit diagnostic message, preventing silent code corruption.
    \item \textbf{\texttt{shell} [cmd]}: Executes system commands via \texttt{subprocess.run}. In interactive mode, shell invocations require human confirmation. In automated or headless runs, shell access is guarded by an explicit \texttt{--allow-shell} flag and a tokenized, prefix-based allowlist (\texttt{--shell-allowlist}).
\end{itemize}

\subsection{Schema-Free Tool Calling via Code Fences}
Most commercial agent frameworks rely on proprietary JSON function-calling formats (e.g., OpenAI Tool Calls, Anthropic Tool Use). However, open-weights and smaller localized models (e.g., 7B--14B parameter models running on consumer GPUs via Ollama) frequently struggle with strict JSON schema serialization, resulting in decoding failures and aborted trajectories.

NakedAgent resolves this via \textit{Markdown Code-Fence Tool Parsing}. The system prompt instructs the language model to invoke tools by emitting standard triple-backtick fenced blocks where the language identifier denotes the tool:
\begin{lstlisting}[language=bash]
```patch src/calculator.py
<<<<<<< SEARCH
def add(a, b):
    return a - b
=======
def add(a, b):
    return a + b
>>>>>>> REPLACE
```
\end{lstlisting}

A deterministic regular expression scanner extracts tool blocks from the generated token stream:
\begin{equation}
    \mathcal{P}_{\text{tool}}: \text{Response} \to \{(\text{name}_i, \text{target}_i, \text{payload}_i)\}_{i=1}^k
\end{equation}
Because every modern instruction-tuned model is pre-trained extensively on Markdown code blocks, tool-calling success rates remain high even on small 7B parameter models without fine-tuned JSON function calling capabilities.

\subsection{Transport Abstraction}
Network transport is implemented via standard \texttt{urllib.request}. NakedAgent natively supports two wire protocols:
\begin{enumerate}
    \item \textbf{Ollama Local API}: Default local inference via \texttt{/api/chat}, operating with zero network exposure.
    \item \textbf{OpenAI-Compatible Wire API}: Supporting vLLM, LM Studio, and remote API gateways using standard Bearer token authentication loaded from environment variables (\texttt{OPENAI\_API\_KEY}).
\end{enumerate}

\section{Provable Execution and Replay Verification}

\subsection{The Mealy Machine State Reducer}
To provide mathematical rigor and eliminate unverified hidden state, NakedAgent models automated runs as a finite state Mealy machine:
\begin{equation}
    \delta: (S_t, E_t) \to (S_{t+1}, [A_{t+1}])
\end{equation}
where $S_t$ is the immutable agent state at turn $t$, $E_t$ is an incoming event, and $A_{t+1}$ represents outward actions dispatched to the environment (such as model requests or tool executions).

The agent state $S_t$ is a frozen dataclass encapsulating:
\begin{equation}
    S = \langle \text{status}, \text{messages}, \text{budget}, \text{pending\_actions}, \text{meta} \rangle
\end{equation}
Transitions are purely functional and side-effect free: all I/O is isolated in a thin driver layer (\texttt{driver.py}).

\subsection{Merkle State Hashing and Event Logging}
Every transition is logged sequentially into an append-only JSONL stream. Each record is cryptographically linked to the preceding state through SHA-256 Merkle chaining:
\begin{equation}
    H_0 = \text{SHA-256}(\text{GenesisHeader})
\end{equation}
\begin{equation}
    H_t = \text{SHA-256}(H_{t-1} \parallel \text{CanonicalJSON}(E_t) \parallel \text{Digest}(S_t))
\end{equation}

This cryptographic formulation guarantees:
\begin{itemize}
    \item \textbf{Tamper Evidence}: Any post-hoc mutation of tool outputs, prompt injections, or agent actions invalidates all downstream hashes in the chain.
    \item \textbf{Strict Causality}: Events cannot be reordered or inserted retroactively.
\end{itemize}

\subsection{Zero-Inference Offline Replay}
Auditing AI agent trajectories historically required either re-executing expensive LLM calls (which introduces non-determinism) or trusting unverified raw text transcripts.

Under NakedAgent, any recorded event log $\mathcal{L} = [e_1, e_2, \dots, e_N]$ can be verified offline via:
\begin{lstlisting}[language=bash]
$ python -m nakedagent.replay run.jsonl
PASS run.jsonl: verified 5 events; final hash 6d1e09...
\end{lstlisting}
The replay verifier re-executes the pure reducer $\delta(S_t, E_t)$ against the recorded tool results without initiating any network calls or model inferences. If the reconstructed Merkle state hash matches the terminal hash in the log, the execution is mathematically certified to have followed the reducer's operational semantics.

\textit{Epistemic Scope}: Importantly, this cryptographic replay certifies \textbf{internal transcript causality and reducer determinism}---specifically, that the internal state transitions $\delta(S_t, E_t) \to S_{t+1}$ followed verified rules without offline transcript tampering. It does \textit{not} certify external semantic correctness, external environment isolation, or model resistance to prompt injection, which must remain defended by OS-level sandboxing.

\section{The Omakase Extensibility Doctrine}

\subsection{Defaults over Decisions}
Inspired by the Japanese concept of \textit{Omakase} (``chef's choice''), NakedAgent provides highly tuned, opinionated defaults: out-of-the-box, a developer requires no configuration flags or parameter tuning.

\subsection{The Plugin Seam}
Extensibility is achieved not through heavyweight frameworks or abstract base classes, but via a filesystem convention seam:
\begin{itemize}
    \item Plugins are plain Python files placed in \texttt{.nakedagent/plugins/} (repo-local) or \texttt{\~{}/.nakedagent/plugins/} (user-global).
    \item A plugin exposes an optional \texttt{TOOLS: dict[str, ToolFunc]} and an optional \texttt{DISABLE: list[str]}.
\end{itemize}

\subsection{Dynamic Prompt Adaptation}
In classical agent architectures, modifying a tool requires manually modifying the system prompt text to reflect the new syntax. In NakedAgent, every tool function attaches an intrinsic \texttt{.usage} metadata attribute. 

When plugins are discovered at startup, the system prompt generator dynamically renders the tool documentation block:
\begin{equation}
    \text{Prompt}_{\text{system}} = \mathcal{B}_{\text{core}} \cup \bigcup_{t \in \mathcal{T}_{\text{active}}} t\text{.usage}
\end{equation}
If a plugin overrides \texttt{patch} with a unified-diff implementation, its replacement \texttt{.usage} example automatically replaces the foundation documentation in the prompt without touching foundation code.

Furthermore, setting \texttt{DISABLE = ['shell', 'write']} prunes both the dispatch registry and the prompt examples, instantly yielding a provably read-only agent.

\section{Sidekick Harness and Safety Tripwires}
For governed environments, NakedAgent incorporates the \textit{Sidekick Harness} and \textit{JevNoulGate} tripwires:
\begin{itemize}
    \item \textbf{Bounded Slot Budgets}: Every autonomous run is assigned a strict maximum turn budget $B_{\text{max}}$. Upon exhaustion, execution transitions immediately to a suspended state without unbounded recursion.
    \item \textbf{Tri-State Escalation}: Sensitive operations (such as high-impact shell commands) pass through a tripwire evaluator yielding $\text{ALLOW}$, $\text{DENY}$, or $\text{ESCALATE}$. In an escalate condition, the event log is sealed in a suspended state awaiting human sign-off.
    \item \textbf{Zero-Dependency MCP Client}: NakedAgent includes a standard-library JSON-RPC 2.0 client supporting the Model Context Protocol (MCP) over \texttt{stdio}, enabling tool sharing across modern agent meshes without external SDKs.
\end{itemize}

\section{Exploratory Pilot: Failure Modes of Local Models under Minimal Scaffolding}

\subsection{Experimental Setup}
To explore the failure dynamics, harness friction, and baseline capabilities of minimal agent architectures under local inference, we conducted an exploratory pilot on SWE-bench Lite~\cite{jimenez2024swebench}.
\begin{itemize}
    \item \textbf{Hardware}: NVIDIA GeForce RTX 3080 Ti (12 GB VRAM), Docker Desktop (WSL2), AMD Ryzen CPU.
    \item \textbf{Model}: Google \texttt{gemma3:12b} served locally via Ollama with 4-bit quantization. Note that while mini-swe-agent was configured with temperature $T=0$, NakedAgent was evaluated under Ollama's default sampling temperature ($\approx 0.8$), which we note as an uncontrolled exploratory variable.
    \item \textbf{Instances}: SWE-bench Lite instances \texttt{astropy\_\_astropy-12907}, \texttt{-14182}, and \texttt{-14365}.
    \item \textbf{Baselines}: Mini-SWE-agent 2.4.6 (native tools mode vs. text-based backtick mode).
\end{itemize}

\subsection{Error Taxonomy: Scaffold vs. Model Bounds}
The pilot revealed critical insights into the interaction between minimal scaffolds and localized language models:
\begin{enumerate}
    \item \textbf{Provider-Native Tool Incompatibility (A1)}: Local Ollama serving of \texttt{gemma3:12b} rejected native function calling schemas outright. Scaffolds strictly bound to provider tool APIs failed before execution began.
    \item \textbf{Syntax Brittle Failures (A2)}: When forced to write raw bash blocks, small models struggled with command escaping and prompt-format compliance, resulting in \texttt{RepeatedFormatError} loops.
    \item \textbf{Placeholder Echoing (C1)}: In early trials, the tool usage prompt included abstract placeholders such as \texttt{<bash command>}. Gemma 3 literally echoed the angle brackets (\texttt{<git status>}), causing bash syntax errors. Replacing prompt placeholders with concrete, literal examples eliminated this error mode.
    \item \textbf{Host OS Newline Ingestion (C2)}: Running on Windows host systems communicating with Linux Docker containers resulted in Windows CRLF ($\backslash r \backslash n$) conversions over text pipes, causing git to treat entire files as modified. NakedAgent resolved this by enforcing binary streams across all tool I/O boundaries.
    \item \textbf{Localized Patching (C3)}: With binary I/O and concrete usage examples, NakedAgent enabled Gemma 3 to localize and generate clean single-hunk patches on complex Astropy files without external diff packages.
    \item \textbf{Syntactic Compliance vs. Semantic Correctness}: Although configuration C3 generated a syntactically valid single-hunk patch on \texttt{astropy-12907}, test-suite evaluation revealed 7 unit test regressions, resulting in 0/3 resolved tasks. Minimal scaffolding effectively removes harness friction, but semantic problem-solving on complex issues remains bounded by local model parameters.
\end{enumerate}

\section{Security Analysis}

\subsection{Attack Surface Elimination}
By enforcing $|\mathcal{D}_{\text{runtime}}| = 0$, NakedAgent eliminates the entire attack surface associated with dependency confusion, typosquatting, compromised sub-dependencies, and unpatched upstream CVEs in network libraries.

\subsection{Shell Sandboxing and Injection Defense}
Because the shell tool is the most sensitive primitive, NakedAgent implements multi-stage defensive gates:
\begin{itemize}
    \item In automated execution, commands must match an approved argv prefix.
    \item Arguments are tokenized using POSIX shell lexical parsing (\texttt{shlex.split}), preventing command-chaining injection attacks (such as semicolons \texttt{;}, logical operators \texttt{\&\&}, or command substitutions \texttt{\$(...)}).
    \item Path validation routines guarantee that file writes cannot escape designated workspace roots via directory traversal (\texttt{../../}).
\end{itemize}

\subsection{Plugin Gating and Protected Surfaces}
Eliminating third-party dependencies does not eliminate environmental risks from untrusted repositories or ambient shell binaries. To prevent repository-drop code execution (where a cloned project includes malicious code in \texttt{.nakedagent/plugins/}), NakedAgent disables workspace-local plugins by default, requiring an explicit \texttt{--trust-plugins} CLI flag. Furthermore, the \texttt{write} and \texttt{patch} tools enforce protected surface boundaries preventing modifications to \texttt{.git/} or \texttt{.nakedagent/}, and automated production workloads are strictly recommended to execute within containerized sandboxes.

\section{Related Work}
\textbf{Coding Agents}: SWE-agent~\cite{yang2024sweagent} introduced specialized agent-computer interfaces (ACI) tailored for repository navigation. Aider~\cite{gauthier2023aider} popularized in-terminal pair programming with git-anchored search/replace editing. OpenHands~\cite{openhands2024} established a generalist agent runtime platform. NakedAgent distinguishes itself by proving that these core capabilities can be achieved without the 30+ package dependencies characteristic of existing systems.

\textbf{Execution Proofs and Governance}: Krineia~\cite{bowlby2026krineia} established formal standards for append-only audit logs in AI governance. NakedAgent implements these principles at the code generation layer through its Merkle-linked Mealy state reducer and zero-inference replay verifier.

\section{Discussion and Limitations}
While standard-library minimalism delivers security and portability, it entails calculated trade-offs:
\begin{itemize}
    \item \textbf{Lack of Streaming UI}: Without third-party libraries like \texttt{rich} or \texttt{blessed}, streaming token visualization in the terminal is intentionally rudimentary.
    \item \textbf{Network Transport}: Using \texttt{urllib.request} lacks built-in HTTP/2 multiplexing and requires manual connection pooling for high-throughput concurrency.
    \item \textbf{Patch Complexity}: The foundation \texttt{patch} tool relies on exact substring matching. While unambiguous, it requires models to reproduce exact surrounding context lines, whereas fuzzy diff engines tolerate minor whitespace variations.
\end{itemize}

\section{Conclusion and Availability}
NakedAgent demonstrates that a zero-runtime-dependency coding agent is not merely a theoretical curiosity, but a robust, auditable, and production-viable architecture. By relying exclusively on Python standard-library primitives, Markdown code-fence parsing, an Omakase plugin seam, and a Merkle-verified Mealy state reducer, NakedAgent provides an uncompromised foundation for autonomous software engineering.
